# CLAUDE.md

Guidance for Claude Code working in this repo.

## What this is

STM32 firmware for an RFID card **top-up / card-management station**. An
STM32L432KC (Cortex-M4F) reads MIFARE cards over an MFRC522 (RC522) on SPI1,
shows a 3-mode UI on an ILI9341 LCD (SPI3) driven by 2 buttons, and talks to an
ESP32 over USART2. The ESP32 bridges UART ↔ MQTT/TLS to HiveMQ; the Go backend
at `../mad-tetris-backend` owns all DB logic. STM32 does no networking itself.

Modes: **ADD MONEY** (check card → pick 20/50/100 → add_money), **NEW GUEST**
(register unregistered card), **REMOVE CARD** (confirm-delete a member).

UART line protocol: STM32 sends `CMD <action> <uid> [amount]`, ESP32 replies
`RESP <topic> OK|ERR [extra]`. Full spec + MQTT mapping in
`docs/topup-station.md`.

Generated by STM32CubeMX (`payment_mqtt.ioc`, CubeMX 6.18.0). This is an
STM32CubeIDE / Eclipse CDT project, **not** a git repo.

## Layout

- `Core/Src/main.c` — entry point. App state machine lives in `/* USER CODE 4 */`:
  `App_Init`/`App_Task` (home menu + mode dispatch), screen helpers, `wait_card`,
  `send_cmd`/`wait_resp` (UART `CMD`/`RESP`), RC522 read, and
  `HAL_GPIO_EXTI_Callback` for the buttons. UART RX via `HAL_UART_RxCpltCallback`
  fills `rx_buffer` until `\r`/`\n`.
- `Core/Src/ili9341.c` / `Core/Inc/ili9341.h` — ILI9341 LCD driver on SPI3
  (`hspi3`), built-in 5x7 ASCII font. Uses `LCD_*_Pin` macros from `main.h`.
- `arduino/top_up_station/top_up_station.ino` — ESP32 UART↔MQTT bridge.
- `Core/Src/RC522.c` / `Core/Src/RC522.h` — MFRC522 driver (SPI reg r/w, Request,
  Anticoll, SelectTag, Auth, Read, Write, Halt). Note: header lives in `Core/Src/`,
  not `Core/Inc/`.
- `Core/Src/{spi,usart,gpio}.c` + `Core/Inc/*.h` — CubeMX-generated peripheral init.
- `Core/Src/stm32l4xx_it.c` — interrupt handlers.
- `Core/Startup/startup_stm32l432kcux.s` — vector table / reset.
- `Drivers/` — STM32L4xx HAL + CMSIS (vendor code, do not edit).
- `Debug/` — generated build output (makefiles, `.elf`, `.map`, `.list`).
- `STM32L432KCUX_FLASH.ld` — linker script.
- `docs/hardware-wiring.md` — full pin map + wiring for RC522, ESP32 UART,
  buttons, and LCD-TFT. Update it whenever the `.ioc` pinout changes.

## Hardware wiring (from RC522.h + .ioc)

- MFRC522 on **SPI1**. CS = PA4, RST = PB0.
- Debug/data UART = **USART2** (also stdout via `__io_putchar`), 115200 assumed.
- `Read_MFRC522(VersionReg=0x37)` should return `0x91`/`0x92` if the RC522 is
  wired correctly — main.c prints a wiring self-test at boot.
- Buttons: BTN1=PA0, BTN2=PA5 — EXTI, internal pull-up, active-low (falling edge).
- LCD-TFT on **SPI3** (PB3=SCK, PB5=MOSI); control pins PA9=CS, PA10=DC,
  PA11=RST, PA12=BL. Separate bus from RC522 (SPI1).
- Full wiring table in `docs/hardware-wiring.md`.

## Build

Toolchain: GNU Tools for STM32 14.3.rel1 (`arm-none-eabi-gcc`), flags target
`cortex-m4` with `-mfpu=fpv4-sp-d16 -mfloat-abi=hard`, `--specs=nano.specs`,
defines `STM32L432xx USE_HAL_DRIVER DEBUG`, `-O0 -g3`.

Normally built from STM32CubeIDE. CLI build via the generated makefiles:

```sh
cd Debug && make -j        # produces Debug/payment_mqtt.elf
make clean                 # from Debug/
```

`Debug/makefile` is auto-generated — do not hand-edit it or the `*.mk` files.

## Conventions

- CubeMX owns peripheral config. Hand-written code must stay between the
  `/* USER CODE BEGIN x */` … `/* USER CODE END x */` markers, or CubeMX
  regeneration (from the `.ioc`) will wipe it. Everything outside is generated.
- Comments and UART strings mix Thai and English — keep existing Thai comments.
- `RC522.c/.h` is third-party-style driver code; keep its `uchar`/`uint` idiom.
